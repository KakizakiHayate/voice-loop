# voice-loop

口と耳だけで、herdr の上の Claude Code と話すためのプラグインです。スマホやブラウザでタップして話し、もう一度タップして送ると、返事が声で返ってきます（トランシーバー式）。

話し相手は2種類あります。

- **個別のセッション**：herdr で動いている Claude Code のセッションをひとつ選んで話します。
- **ハブ**：全セッションを見渡す役のセッションです。「全体どうなってる？」に答え、「〇〇に△△を頼んで」で指示を送り、頼んだ件が片づくと声で知らせます。

## しくみ

```
ブラウザ（タップして話す）
  → 聞き取り（whisper）        声を文字にする
  → herdr → Claude Code         セッションに送り、返事を記録から読む
  → 語り手（軽いモデル）        返事を話し言葉に直す
  → 声（AivisSpeech か VOICEVOX）読み上げる
  → ブラウザで再生
```

本体（`server.py`）は launchd の常駐サービスとして動きます。プラグインは、その上げ下ろしと初回の準備を受け持つだけです。herdr を閉じても動き続け、Mac を再起動したあとは launchd が上げ直す作りです。

## 準備

macOS 専用です。次のものが要ります。足りないものは、あとで `doctor` が教えます。

| 要るもの | 何に使うか |
|---|---|
| herdr 0.9.3 以上 | セッションの一覧・送信・画面の読み取り |
| Claude Code と、herdr の Claude 連携 | 話し相手。連携が無いと返事を記録から読めません |
| uv | 本体とハブの道具の実行 |
| whisper のサーバー | 聞き取り |
| AivisSpeech Engine（または VOICEVOX Engine） | 声 |
| Anthropic の API の認証 | 語り手（返事を話し言葉に直すモデル） |
| Tailscale（任意） | スマホから使うとき |

### herdr と Claude Code

voice-loop は、herdr と Claude Code が動いている Mac に入れます。セッションの記録と herdr を、同じ Mac の上で読むためです。Claude Code はログインを済ませておき、herdr の Claude 連携を入れます。

```sh
herdr integration install claude
```

### uv

```sh
brew install uv
```

### 聞き取り（whisper）

`127.0.0.1:8080` で、OpenAI 互換の `/v1/audio/transcriptions` に応えるサーバーを立てます。whisper.cpp の例です（モデルは約1.6GB）。

```sh
brew install whisper.cpp ffmpeg
mkdir -p ~/.local/share/whisper-models ~/.local/state/whisper-work
curl -L -o ~/.local/share/whisper-models/ggml-large-v3-turbo.bin \
  https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-large-v3-turbo.bin
cd ~/.local/state/whisper-work && whisper-server \
  -m ~/.local/share/whisper-models/ggml-large-v3-turbo.bin \
  --host 127.0.0.1 --port 8080 --inference-path /v1/audio/transcriptions -l ja --convert
```

最後の `whisper-server` は、止めるまで動き続けます。別のタブで実行して、開いたままにしてください。

`--convert` は、ブラウザの録音を ffmpeg で変換するために要ります。変換は作業フォルダに一時ファイルを書くので、書き込めるフォルダで起動してください。launchd に登録して常駐させるときは、`WorkingDirectory` を忘れると変換に失敗します。

### 声（AivisSpeech）

`127.0.0.1:10101` で AivisSpeech Engine を動かします。Docker の例です（イメージは約3.7GB）。Docker を動かすもの（OrbStack や Docker Desktop）が要ります。OrbStack なら `brew install --cask orbstack` で入れ、一度アプリを開いて初期設定を済ませます。

```sh
docker run -d --name aivis --restart unless-stopped \
  -p 127.0.0.1:10101:10101 ghcr.io/aivis-project/aivisspeech-engine:cpu-latest
```

### 軽い声にするなら（VOICEVOX）

AivisSpeech は CPU だけで計算し（Mac の GPU には対応していません）、待機中もメモリを約1.9GB使います。メモリの少ない Mac では、代わりに VOICEVOX Engine を使えます。声の顔ぶれは変わります。

作者の Mac mini（M4 Pro）で、約6秒の文を作るのにかかった時間です。

| | 1文の合成 | 待機中のメモリ | イメージ |
|---|---|---|---|
| AivisSpeech | 2.0〜3.1 秒 | 1.86GB | 3.7GB |
| VOICEVOX | 0.8〜1.0 秒 | 78MB | 2.3GB |

```sh
docker run -d --name voicevox --restart unless-stopped \
  -p 127.0.0.1:50021:50021 voicevox/voicevox_engine:cpu-latest
```

設定フォルダの `config.env` に `VL_VOICE=voicevox` と書き、`restart` します。既定の声は春日部つむぎで、画面でほかの声を選べます。`config.env` で `VL_DEFAULT_SPEAKER` を書いているなら、その行を消すか、VOICEVOX の声の ID に直してください。AivisSpeech の声の ID のままだと、点検が「既定の声」で知らせます。

VOICEVOX の[利用規約](https://voicevox.hiroshiba.jp/term/)では、使うときに VOICEVOX を使ったことがわかるクレジットの表記（「VOICEVOX:春日部つむぎ」など）が要ります。声ごとの規約にも従います。

### 語り手の認証

語り手は Anthropic の API を呼びます。Claude のサブスクリプションとは別に、API の利用料がかかります（既定の Claude Haiku 4.5 で、200字ほどの返事1回あたり約0.3円。作者の環境での実測）。認証は次のどちらかです。

- Anthropic の CLI でログインする：`brew install anthropics/tap/ant` のあと `ant auth login`
- API キーを使う：設定フォルダの `config.env` に `ANTHROPIC_API_KEY=...` を書く

## 入れ方

```sh
herdr plugin install u-space-inc/voice-loop
herdr plugin action invoke u-space.voice-loop.start
```

手元に置いたフォルダから使うなら、`herdr plugin link <フォルダ>` で登録します。

`start` は、設定フォルダにひな形を置き、常駐サービスを登録して上げ、ハブを立て、最後に点検の結果を出します。手でやることが残っていれば、番号つきで並びます。

`herdr plugin action invoke` は、受け付けたことを JSON で返すだけです。結果は次の命令で読みます。1行目が `start running` なら、まだ準備の途中です。初回は必要なものの取得で数分かかることがあるので、少し待って打ち直してください。

```sh
herdr plugin log list --plugin u-space.voice-loop | python3 -c '
import json, sys
logs = json.load(sys.stdin)["result"]["logs"]
if not logs: sys.exit("記録なし")
last = logs[-1]
print(last["action_id"], last["status"])
print(last.get("stdout") or "", last.get("stderr") or "")'
```

「記録なし」は、プラグインが入っていないときにも出ます。入っているかどうかは `herdr plugin list` で確かめます。

## 初回に、手で答えること

ハブを初めて立てると、herdr の `hub` タブで Claude Code が「このフォルダを信頼しますか」と聞いて止まります。**↓ で「Yes, I trust this folder」を選び、Enter を押してください。** 初めの選択は「No, exit」なので、Enter だけでは進みません。

この確認が出るのは、ハブの作業フォルダが次の設定を持っているためです。

- `./hubctl`（ハブの道具）は、確認なしで実行できる
- ファイルを書く道具（Edit / Write）は使えない
- Bash で実行できるのは `./hubctl` だけ（それ以外は見張りが止める）

答えたあと、もう一度 `start` を実行するか、画面の「ハブを起動」を押します。ログインなど、ほかの画面で止まっているときも同じで、端末で答えてから `start` です。voice-loop がこれらの画面に代わりに答えることはありません。

ハブに新しいセッションを立てさせたとき、そのプロジェクトで Claude Code を初めて起動するなら、同じ確認がそのタブに出ます。これも手で答えます。

## 使い方

`start` が出す URL を開きます。スマホから使うなら、Tailscale で https にして開きます（スマホのマイクは https でないと使えません）。

```sh
tailscale serve --bg --https=8790 http://127.0.0.1:8790
```

話し相手を選び、「タップして話す」を押して話し、もう一度押して送ります。初めて開いたときの話し相手はハブです。準備が残っていると、画面にも同じ案内が出ます。

声を出せない場所では、状態の欄の「🔇」で読み上げを切れます。切っている間は、返答もハブからの報告も文字だけで出て、音は鳴りません（報告が届いた知らせの音もありません）。読み上げの途中で押すと、その場で声が止まります。「停止」と違い、考え中の返答は止めずに文字で届きます。もう一度押すと、次の返答から読み上げます。切ったかどうかは端末ごとに覚えます（スマホは文字だけ、パソコンは声、のように分けられます）。読み上げない間は、本体も語り手と声のエンジンを呼びません。

どれかのセッションが承認で止まると、話し相手の画面のまま、画面の上にそのセッションの名前と、何を聞かれているかと、「許可（今回だけ）」「断る」のボタンが出ます。いくつ止まっていても、すべて並びます。許可は今回だけで、「今後は聞かずに許可」は選びません。削除や送信など取り消しにくい操作に見えるときは、もう一度押すと許可します。押すと、送る直前に同じ問いのままかを確かめ、変わっていれば送らずに出し直します。

ボタンが出るのは、承認の画面と見分けられたときだけです。選択式の質問、フォルダを信頼するかの確認、読み取れない画面は、名前と中身だけを出します。答えは端末か、ハブに話して伝えます。

画面を閉じていても知らせを受け取るには、状態の欄の「🔔」を押します。頼んだ件が片づいたとき（続きの返答・裏で作業を続けている・セッションが見つからなくなったときも）と、どれかのセッションが承認・入力待ちで止まったときに、プッシュ通知が届きます。押すと voice-loop が開きます。

- 送るのは、voice-loop の画面がどれも見えていないときだけです。見えている画面には、これまでどおり声と文字で届きます。画面は見えている間、20秒ごとにそのことを本体に知らせ直し、45秒途切れると見えていないとみなします（スマホで裏に回したことが本体に届かなくても、通知が止まったままにならないように）。
- 頼んだ件の通知は、ハブの報告ができた時点で送ります。ハブが話し中などで30秒たっても報告ができないときは、先に送ります（「ハブの報告は、このあと届きます」と添えます）。
- 通知に載るのは「案件｜件名」と、何が起きたかだけです。結果の中身は、開いてハブの報告で読みます。通知はブラウザの配送サービス（iPhone なら Apple）を通りますが、中身は端末の鍵で暗号化され、配送の側では読めません。
- iPhone では、ホーム画面に追加した voice-loop から押します（Safari のタブでは受け取れません）。初めて押すと、通知を許可するか聞かれます。許可すると、試しの通知が届きます。
- もう一度押すと切れます。端末ごとに入れたり切ったりできます。
- 配送サービスには、困ったときの連絡先を伝えます。`config.env` の `VL_PUSH_SUBJECT` に `mailto:あなたのアドレス` を書いてください（書かなければ、届かない宛先を名乗ります）。
- 承認・入力待ちは、ハブ経由で頼んだ件かどうかに関係なく、止まって1分たっても止まったままのときに1回知らせます（Mac の前ですぐ答える承認では鳴りません）。待つ秒数は `config.env` の `VL_BLOCKED_NOTIFY_AFTER` で変えられます。🔔 を入れたときや本体が起動したときに、もう止まっていたものは知らせません。

「📋」で、ハブ経由で頼んだ件の一覧が開きます。送った指示・立てたセッション・答えた承認ごとに、いまの状態（見張り中・承認・入力待ち・完了・見失った、など）が出ます。ハブに「今頼んでる件は？」と聞いても答えます（`hubctl tasks`）。本体の再起動や `off` で見張りが切れた件も、「見張りが切れた」と残ります。終わった件は3日で消えます。

「💡」で、いまの状況が開きます（下の「いまの状況」）。ハブが知っている話題と、覚えていることの一覧です。ここで覚えさせる・× で忘れさせることもできます。拾う役が出した提案（セッションへの指示の案）もここに出て、読んで「送る」を押すと、そのフォルダに新しいセッションを立てて頼みます（下の「提案」）。

つながらないときも、一度開いたことのある端末なら画面は開き、「接続できません。接続を確かめてください」と出ます。そのあいだは送れません（打ちかけの文は残ります）。つながると、読み込み直さずにその場で戻ります。

更新したあとは、状態の欄の右端の「↻」で最新の画面に読み込み直せます（ホーム画面に追加したアプリには、ブラウザの読み込み直しがないため）。手元に取っておいた画面ではなく本体から取り直し、取れないときは今の画面のまま「接続できません。接続を確かめてください」と出ます。

## 接続できる範囲

本体は `127.0.0.1` でだけ待ち受けます。使えるのは、この Mac の上のプログラムと、Tailscale Serve を通した tailnet の端末です。

- この範囲の中からなら、パスワードなしでセッションへ指示を送れます。tailnet をほかの人と共有しているときは、Tailscale のアクセス制御で、この Mac の 8790 番を自分の端末だけに絞ってください。
- `tailscale funnel` でインターネットに公開しないでください。
- ブラウザで開いたほかのサイトからの接続は、本体が断ります。接続元（Origin）と宛先の名前（Host）を確かめています。断ったときは、ログに `[guard]` で始まる行が残ります。
- この Mac の名前と Tailscale の名前（〜.ts.net）以外で画面を開くときは、`config.env` の `VL_ALLOWED_HOSTS` にその名前を書きます。
- Docker のコンテナからは `host.docker.internal` という名前で届きます。そこからは、Hermes の `hubctl` が使う `/api/hub/…` の口だけを、鍵（`hub_key`。Hermes の API サーバーの鍵と同じ値）が付いているときに通します。画面を開く・WebSocket・画面用の API は断ります。
- コンテナの中からは、宛先の名前（Host）を `127.0.0.1` などと偽ることができ、接続元もこの Mac の `127.0.0.1` に見えます。そこで本体は、この Mac の上からの接続ごとに、もとのプログラムを `lsof` で調べます。コンテナの中継のプログラム（OrbStack・Docker）からなら、宛先の名前に関係なくコンテナからの接続として扱います。調べられなかったときも、コンテナとして扱います（通さない側に倒します）。ほかの中継のプログラムを使っているときは、`config.env` の `VL_CONTAINER_PROGRAMS` に名前の頭を書きます（例: `podman,colima`）。接続元は本当の接続の相手で見て、`X-Forwarded-For` では書き換えません。
- コンテナからは、この Mac の Tailscale の名前（〜.ts.net）でも、Tailscale Serve を通って届きます。Tailscale Serve が知らせる接続元が、この Mac 自身の住所になっている接続は、コンテナからの接続として扱います。このため、**この Mac の上で画面を開くときは `http://127.0.0.1:8790` を使います**（この Mac のブラウザから Tailscale の名前で開くと、画面の口は断られます）。スマホやほかの端末からは、これまでどおり Tailscale の名前で開けます。

## 命令

どれも `herdr plugin action invoke u-space.voice-loop.<名前>` で呼びます。出力は `herdr plugin log list --plugin u-space.voice-loop` で読めます。

| 名前 | すること |
|---|---|
| `start` | 初回の準備と起動。何度実行してもかまいません |
| `stop` | 止める（herdr や Mac を再起動すると、また上がります） |
| `off` | メモリを空けるために止める。本体と、指定した部品をまとめて止め、`on` まで上がりません |
| `on` | `off` で止めたものを上げ直す（`start` と同じ点検まで） |
| `restart` | 再起動。設定を変えたあとに |
| `status` | サービス・ハブ・語り手の状態と URL |
| `url` | 開く URL |
| `doctor` | 点検。足りないものと、次にやること |
| `uninstall` | 常駐の登録を外す（設定は残ります） |

### off と on（メモリを空ける）

使わない間は `off` で止めて、メモリを空けられます。本体はほとんどメモリを使わず、多く使うのは声のエンジン（AivisSpeech）や聞き取り（whisper）です。まわりの部品もまとめて止めると効きます。

- 一緒に止める部品は、`config.env` の `VL_OFF_CONTAINERS`（コンテナ名）と `VL_OFF_SERVICES`（launchd のサービスのラベル）に書きます。たとえば声のエンジンと Hermes を Docker で動かしているなら `VL_OFF_CONTAINERS=aivis hermes` です。書かなければ、止めるのは本体だけです
- `off` にすると、`on` にするまで、herdr や Mac を再起動しても上がりません。`start` と `restart` も `on` として動きます
- 再起動の設定が `always` のコンテナは、手で止めても Docker が立ち上がり直すと戻るので、`off` の間だけ `unless-stopped` に替え、`on` で戻します
- `on` が戻すのは、`off` で止めたものだけです。`off` していなければ、本体を起動するだけです
- `on` で戻しきれなかったもの（Docker が動いていなかった、など）は記録に残り、`status` に出ます。もう一度 `on` で戻せます
- ほかのツールも使っている部品（聞き取りの whisper を別の音声入力でも使っている、など）を書くと、`off` の間はそのツールからも使えなくなります
- `off` の間は画面も止まるので、スマホからは `on` にできません。Mac の herdr から `on` を呼びます
- 頼んだ件の見張り（片づいたら知らせる）は、`off` にすると消えます

## 設定

端末ごとのものは、本体の外の設定フォルダ（`~/.config/herdr/plugins/config/u-space.voice-loop/`）にあります。プラグインを入れ直しても消えません。

| ファイル | 中身 |
|---|---|
| `config.env` | 設定。行頭の `#` を外すと有効になります。変えたら `restart` |
| `readings.txt` | 読み上げで読み間違える語の読み替え（`語=よみ`）。変えたら `restart` |
| `hub/CLAUDE.md` | ハブへの指示文。呼ばれたい名前やプロジェクトの呼び方を足せます。変えたらハブのタブを閉じて `start` |
| `hub/speaking.md` | ハブの話し方の決まり（長さ、箇条書きにしない、など） |
| `narrator_model` | 語り手のモデル名を1行。書くと再起動なしで切り替わり、消すと既定に戻ります |
| `intake/instructions.md` | 拾う役（いまの状況をまとめる）への指示文。あなたの呼ばれ方の聞き間違いなどを足せます。次の回から効きます |
| `push/vapid_private.pem` | プッシュ通知の鍵。初めて 🔔 を押したときに本体が作ります。消すと、登録した端末に届かなくなります（もう一度 🔔 を押し直します） |

ハブに新しいセッションを立てさせるには、`config.env` の `VL_PROJECTS_DIR` にプロジェクトの置き場所を書きます。立てられるのは、その直下にある既存のフォルダだけです。

ログは `~/.local/state/herdr/plugins/u-space.voice-loop/server.log` です。同じフォルダに、通知の届け先（`push-subscriptions.json`）と頼んだ件の台帳（`delegations.json`）、いまの状況（`situation.json`・`facts.json`・`intake-runs.jsonl`）を置きます。

以前の版から更新したときは、設定フォルダのハブへの指示文（`hub/CLAUDE.md`、Hermes なら `hermes/hub.md`）は書き換えません。ハブに「今頼んでる件は？」で答えてほしいときは、`templates/` の同じファイルの「道具」の欄から `hubctl tasks` の行を写します。いまの状況を Claude Code のハブに使わせるときは、「道具」の欄の `hubctl context`・`remember`・`forget` の行と、「いまの状況と、覚えていること」の節を写します（Hermes のハブには、本体が毎回の案内として足すので、写さなくても使えます）。0.11.0 の提案を使うときは、設定フォルダの `intake/instructions.md` に、`templates/intake/instructions.md` の「提案（セッションへの指示の案）」の節と、「入力」の `topics`・`proposals` の行、「結果の返し方」の `propose` の行を写します（写さなければ提案は出ない作りです。拾う役には、出力の提案の欄を、節が無ければ空で返すよう伝えています）。Claude Code のハブには、「道具」の欄の `hubctl proposals` の行と、「いまの状況と、覚えていること」の節の提案の行を写します。

## ハブがすること・しないこと

ハブはほかのセッションの記録を読むので、そこに紛れた指示に乗せられないよう、できることを絞ってあります。

- 指示は、確認を挟まずに送ります。そのかわり、何をどこへ送ったかを必ず声で伝えます。
- 承認や質問で止まっているセッションには、あなたの答えを伝えるだけです。中身を声で伝えたあと、あなたの次の発言で答えを聞きます。本番への反映、送信、削除など取り消しにくい操作は、もう一度聞き返します。
- 「今後は聞かずに許可」にあたる選択肢は選びません。フォルダの信頼の確認にも答えません。
- セッションを閉じるのは、あなたが頼み、許可したときだけです。どのセッションを閉じるかをプロジェクト名で声で伝え、あなたの次の発言が「はい」「お願い」などのはっきりした許可のときに閉じます。本体もハブの記録でこの順序と言葉を確かめ、満たさなければ閉じません。閉じるとその画面が消えます（タブにほかの画面が無ければタブも。会話の記録は残ります）。
- 自分ではファイルを書かず、`./hubctl` 以外のコマンドも実行しません。

## いまの状況（録音・予定・メールから）

ハブが、あなたがいま抱えている話を知るための仕組みです（既定は切。`config.env` の `VL_INTAKE=1` で動きます）。決まった時間（既定は平日 9〜19 時の毎時5分）に、本体が「拾う役」の Claude Code（`claude -p`）を動かし、あなたの録音（Plaud）・予定（Google カレンダー）・メール（Gmail）を読ませて、「話題」の一覧をまとめ直します。ハブは、あなたの用事や予定の話が出たときに `hubctl context` で読みます。

- **正本は持ちません。** 正本は録音・予定・メールの側で、ここにあるのはそこからの要約です。おかしくなったら `situation.json` を消せば、次の回から作り直します。
- **手入れは要りません。** 終わった話は拾う役が外し、動きの無い話（既定 21 日。先の予定があるものは残す）は本体が外します。外れた話題は 7 日のあいだ「最近外れた話題」に残ります。あなたが一覧を閉じたり消したりする操作はありません。
- **話題は案件とは限りません。** まだ案件になっていない相談や、人との定期的な情報交換の場も話題です。関係するフォルダがはっきりしているときだけ、フォルダ名が付きます。
- **私用は入れません。** 趣味や家族などの録音は、題名も中身も残さず、数だけ数えます（判断は拾う役の Claude がするので、見分け違いはありえます）。
- **覚えていること**は、あなたがはっきり言ったことです。ハブに「〜って覚えておいて」と言うか、画面の 💡 で打ちます。拾う役もハブも、推測よりこちらを優先します。「メモの3番を忘れて」か、画面の × で忘れます。進み具合や宿題を書きためる場所ではありません（人が更新しないと嘘になる台帳を、また作らないため）。
- 毎朝の最初の回のあと、どの画面も見えていなければ、朝のまとめ（話題の数・今日の予定に関係する話題の数・外れた話題の数）をプッシュ通知で1通送ります。3回続けて失敗したときも1通送ります。どちらも数だけで、中身は載せません。
- 1 回に詳しく読むのは、録音 6 本・メールのスレッド 10 本までです。読みきれなかった分は次の回に回します。1 回の上限は `VL_INTAKE_BUDGET`（既定 1.00 ドル相当）で、Claude Code の枠で動きます（API キーは要りません）。回ごとの結果（時刻・成否・数・費用）は `intake-runs.jsonl` と画面の 💡 に出ます。読んだ中身は記録に残しません。

使う前に、Claude Code で claude.ai の連携（Plaud・Google Calendar・Gmail）をつないでおきます。メールを見る相手は `VL_INTAKE_DOMAINS`、あなたの宛先は `VL_INTAKE_ADDRESSES` に書きます（書かなければメールは見ません）。

### 拾う役にできること・できないこと

- 使えるのは、録音・予定・メールを**読む**道具だけです（Plaud の `list_files`・`get_note`・`get_transcript`、カレンダーの `list_events`・`search_events`・`get_event`、Gmail の `search_threads`・`get_thread`）。Bash やファイルの読み書き、Web、送る・作る・消す道具はありません。
- あなたの Claude Code の設定で「確認なしで許可」にしてある道具（たとえば Slack への送信）も、拾う役では止まります。止めるのは、本体が拾う役に渡す見張り（`scripts/intake_hook.py`）で、許可した名前と完全に一致する道具の呼び出しだけを通します。見張りが動かないときも、通さない側に倒れます。
- 拾う役が書けるのは、話題の差分と提案（案）だけです。覚えていることは書けず、提案をセッションに送ることもできません。結果は決まった形の JSON で受け取り、本体が形と字数を確かめてから保存します。
- 拾う役の Claude Code の会話は残しません（`--no-session-persistence`）。

### 提案（セッションへの指示の案）

拾う役は、話題の中に、あなたの番で、そのフォルダのセッションに頼めば片づく作業（調べる・まとめる・下書き・資料・コードの変更案）を見つけると、提案を 1 つ出します。外の人への連絡、支払い、本番への反映、削除は提案しません（指示文の決まりです。本体では全部は見分けられません）。

- 画面の 💡 のいちばん上に、フォルダ・なぜ今か・指示の文が出ます。「送る」を押すと確かめが出て、もう一度押すと、そのフォルダに新しいセッション（opus）を立てて、その文を最初の指示として送ります。送った件は 📋 に「提案から」で載り、片づくとハブが報告します。
- **放っておけば消えます。** 3 日たつ・話題が外れる・話題の中身（いま・次・フォルダ・予定の日）が変わる・同じ話題に新しい提案が出る、で閉じます。「見送る」は押さなくてかまいません。閉じた提案は 7 日のあいだ「閉じた提案」に残ります。
- 少なく出します。1 回の巡回で 1 件まで、開いている提案は 3 件まで、1 つの話題に 1 件です。前に提案に使った出どころ（録音・メール・予定）だけを根拠にした提案は、本体が受け付けません（同じ提案が出直さないため）。提案が出るのはフォルダが付いている話題だけです。
- 新しい提案が出た回に、どの画面も見えていなければ、「提案が1件あります: フォルダ名」をプッシュ通知で 1 通送ります（朝の回なら朝のまとめに入れます）。文は載せません。
- 文を直す機能はありません。違う形で頼みたいときは、ハブにいつもどおり頼みます。送り先はいつも新しいセッションです（既存のセッションの仕事に混ぜないため。作業フォルダは同じです）。
- 送る途中で問題が起きたときは、立てたセッションを残し、提案は開いた状態に戻しません（もう一度押して、またセッションが増えるのを防ぐため）。「閉じた提案」に、送れていない・送れたか分からない、と理由つきで出るので、様子を見て、要ればハブに頼みます。セッションを立てる前に断られたと分かっているときだけ、もう一度押せます。
- 提案の文に、取り消しにくい操作（送信・公開・削除・本番など）にかかわる語があれば、画面に目印を付けます（断りはしません。語に当たらない危ない指示もあるので、目印が無いから安全とは言えません）。

### 残る危険

- **提案の文が、あなたが 💡 で押さずに送られることはありません。** 提案を送る口は画面にだけあり、ハブ（Hermes のコンテナを含む）からは使えません。ただし、ハブがふだん使う `hubctl send`・`start`（「〜に送って」）は、これまでどおりハブの判断で送ります。本体が断れるのは、本体が持っている提案（開いているもの・閉じて 7 日以内のもの）の文の写しまでです。提案や話題を読んだハブが、言い換えた文を作って送ることは防げません（下の話題の危険と同じ種類です）。
- 送った先のセッションは、あなたの Claude Code の許可設定のまま動きます。外に出す操作が必ず承認で止まるとは限りません（設定しだいです）。提案の文は、押す前に読んでください。

- 話題はメールや録音の要約なので、悪意のある文面が要約に混ざることはありえます。ハブは話題を引用データとして読み、それを理由に送ったり立てたりしない決まりで、Hermes には毎回の案内にも本文を入れません（数と時刻だけ）。それでも、あなたとの会話の中でハブが話題に引きずられて指示を作ることは、ゼロにはできません。送った文は必ず声で読み上げられるので、聞いておかしければ止めてください（`hubctl read` で他のセッションの記録を読むときと同じ種類の危険です）。
- 覚える文と忘れる番号は、本体がハブの記録にあるあなたの最後の発言から取り出します（ハブが作った文は覚えません）。声の聞き間違いはそのまま残るので、画面の 💡 で確かめて、違えば消してください。

## Hermes をハブにする（試験中）

[Hermes Agent](https://hermes-agent.nousresearch.com/)（Nous Research の自律エージェント）を、ハブの頭にできます。`config.env` で `VL_HUB=hermes` にすると、herdr の中の Claude Code の代わりに、Docker の中の Hermes がハブになります。読む・送る・承認に答える・立てる・閉じるの決まりは同じで、守り（止まっている相手には送らない、承認は見たあとのユーザーの発言でしか答えない、取り消しにくい操作は聞き返す、閉じるのははっきりした許可の次の発言だけ、通知への応答中は操作しない）は本体の側にあるので、頭を替えても変わりません。

Claude Code のハブと違うのは、Hermes が自分の記憶とスキルを持ち、直されたことを自分で書き残そうとする点です。スキルの書き込みは承認してから採用する設定にします（下の「使い方」）。

```
ブラウザ → 本体 → Hermes の API サーバー（Docker の中、同じ会話を続ける）
                       └→ hubctl → 本体の /api/hub/…（host.docker.internal 経由、鍵つき）→ herdr の各セッション
```

`VL_HUB` を書かなければ、これまでどおり Claude Code がハブで、Hermes は話し相手の 1 人として一覧に出るだけです（`VL_HERMES_KEY` を書いたとき）。

### 用意

Hermes は公式の Docker イメージで動かします（Docker を動かすものが要ります）。設定は `~/.hermes` に残ります。

```sh
mkdir -p ~/.hermes
docker pull nousresearch/hermes-agent:latest
# 作業フォルダ（指示文の置き場）、スキルの書き込みは承認してから、API サーバーの鍵
docker run --rm -v ~/.hermes:/opt/data nousresearch/hermes-agent config set terminal.cwd /opt/voice-loop
docker run --rm -v ~/.hermes:/opt/data nousresearch/hermes-agent config set skills.write_approval true
docker run --rm -v ~/.hermes:/opt/data nousresearch/hermes-agent config set API_SERVER_ENABLED true
docker run --rm -v ~/.hermes:/opt/data nousresearch/hermes-agent config set API_SERVER_HOST 0.0.0.0
docker run --rm -v ~/.hermes:/opt/data nousresearch/hermes-agent config set API_SERVER_KEY "$(openssl rand -hex 32)"
```

モデルと認証は、対話の設定で選びます（Anthropic の API キー、Nous Portal など。Claude の個人プランの OAuth は使えません）。

```sh
docker run -it --rm -v ~/.hermes:/opt/data nousresearch/hermes-agent model
```

`config.env` に、同じ鍵と、ハブの頭を書きます（鍵は `~/.hermes/.env` の `API_SERVER_KEY` と同じ値）。書いたら `restart` します。`start` か `restart` で、設定フォルダの `hermes/` に指示文 `hub.md`、道具 `hubctl`、鍵 `hub_key`（コンテナからの接続に付ける。同じ値）が置かれます。

```
VL_HERMES_KEY=（同じ鍵）
VL_HUB=hermes
```

コンテナを常駐させます。設定フォルダの `hermes/` を `/opt/voice-loop` として読み取り専用で見せ、API サーバーはこの Mac の上からだけ使えるようにします。

```sh
docker run -d --name hermes --restart unless-stopped \
  -v ~/.hermes:/opt/data \
  -v ~/.config/herdr/plugins/config/u-space.voice-loop/hermes:/opt/voice-loop:ro \
  -p 127.0.0.1:8642:8642 \
  nousresearch/hermes-agent gateway run
```

話し相手の一覧の先頭に「ハブ（Hermes）｜全セッションを統括」が出ます。`doctor` の「ハブ」の項目が Hermes の確認に変わります。hub フォルダの Claude Code は立てません（残っていれば、ただのセッションとして一覧に出ます）。

### 使い方と、スキルの確かめ方

- 使い方はハブと同じです。気に入らなければ声で直します（「予定は要らない」「件数から言って」など）。会話は `VL_HERMES_SESSION`（既定 `voice-loop`）の名前で続くので、直したことは次の返事に効きます
- 画面に出す Hermes との会話は、本体が状態フォルダの `hermes-log.jsonl` に書いた記録から描きます（ユーザーの発言・返事・自動通知とハブの報告・届かなかったこと）。画面を閉じていた間の返事や報告も、開き直すと出ます。送ったあとで画面を閉じても、本体は返事を最後まで待って記録します。記録が 8MB を超えると `hermes-log.1.jsonl` に回します（一つ前の分だけ残します）。Claude Code のハブと切り替えても、それぞれの記録は残ります
- 指示文（`hermes/hub.md`）は、本体が発言のたびに読んで Hermes に渡します。書き換えは次の発言から効き、会話はそのまま続きます（`AGENTS.md` という名前にしないこと。Hermes はその名前のファイルを会話の始まりに一度だけ読み、以後は古いまま使い続けます。2026-10-21 に確認）
- Hermes がスキルを書こうとすると、承認待ちになります（`skills.write_approval`）。確かめて採用します。`~/.hermes/skills` を git に入れておくと、何がいつ変わったかが残ります

```sh
docker exec -it hermes hermes   # 対話の画面で
/skills pending                  # 保留中のスキルの書き込み
/skills diff <id>                # 差分
/skills approve <id>             # 採用（reject で捨てる）
```

- 一問一答（`hermes chat -q`）では Hermes はスキルを書きません（公式ドキュメント: one-shot では `skill_manage` を外す）。本体が API サーバー経由で同じ会話を続けているのはそのためです
- Hermes は `hubctl` が返す内容（各セッションの記録の引用）を読みます。そこに紛れた指示には従わないよう指示文に書いてありますが、確実ではありません。乗せられても、本体の守りの外（承認を勝手に通す、閉じる、ユーザーの知らない連鎖）には出られない作りです。起きうるのは「変な報告」と「変な指示文を送る」までで、後者は送られたセッションの許可の確認で止まります

### Hermes との会話をターミナルで見る（2026-10-21 に確かめた範囲）

voice-loop が API で続けている会話は、Hermes 側ではふつうのセッション（ID は `VL_HERMES_SESSION` の値）として残る。目で見たいときは、任意のターミナルで次を打つと、その時点までの履歴が開く。

```
docker exec -it hermes hermes --resume voice-loop
```

- 生中継ではない。繋いだあとに voice-loop から送った発言は画面に流れてこない。見直すときは `/quit` で閉じて繋ぎ直す
- `hermes --tui --resume` は、他の端末が開いている会話には繋げない（0.22.2 の Docker 版で「この build では使えない」と出る）
- ターミナルを閉じるときは必ず `/quit`。ウィンドウを消すだけだと、コンテナの中に CLI が残り、そのセッションが「別の端末で開いている」扱いのまま繋ぎ直せなくなる（voice-loop からの発言は影響なく通る）。残ったときは `docker exec hermes sh -c 'pkill -f "resume voice-loop"'`
- Web ダッシュボード（`HERMES_DASHBOARD=1` と `-p 127.0.0.1:9119:9119` を付けてコンテナを作り直す）は未検証

## 更新と、外し方

herdr に更新の命令は無いので、入れ直します。設定フォルダはそのまま残ります。本体の場所や版が変わっていれば、次に herdr を起動したとき（または `start` のとき）に、常駐サービスが新しい本体に切り替わります。

ハブへの指示文（設定フォルダの `hub/CLAUDE.md`。Hermes なら `hermes/hub.md`）は、更新しても上書きされません。新しい版でひな形（`templates/hub/CLAUDE.md`・`templates/hermes/hub.md`）が変わったときは、見比べて取り込み、ハブのタブを閉じて `start` してください（Hermes は次の発言から読み直します）。

外すときは、`uninstall` で常駐の登録を外してから、herdr でプラグインを外します。設定フォルダは残るので、要らなければ手で消します。
