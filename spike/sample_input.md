家計簿アプリのコードを読み終えました。安全面は問題ありませんが、いまの使い方に対して設計が合っていない点がコードから分かったので、手を入れる前に一度報告します。

## レビュー結果

**安全面は問題なし**
- 外部ライブラリへの依存は2つだけで、本体は Python 約3,200行です。
- 通信先は、選んだ銀行の API と、手元の SQLite だけです。
- 書き込みを伴う操作は、既定で確認を挟みます。

**いまの使い方に合わない点**

1. **月をまたぐ取引が二重に数えられる**：締め日の判定が日付の文字列比較です（`ledger.py:118`）。
2. **カテゴリを1つしか付けられない**：表の設計が1対1です（`schema.sql`）。
3. **端数処理が切り捨て固定**：税込みの計算で1円ずれることがあります（`tax.py:42`）。
4. **スマホから入力できない**：macOS のメニューバーから開く前提です。

| 案 | 長所 | 短所 |
|---|---|---|
| A 作り直す | 設計を用途に合わせられる | 時間がかかる |
| B 部分的に直す | すぐ使える | 2と4は残る |

次の進め方を選んでください。A か B か、それとも C（まず1か月そのまま使う）か。
